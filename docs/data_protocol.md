# ETTh1 数据来源、校验与划分证据

## 数据来源

原始文件来自数据集作者的 [ETDataset 官方仓库](https://github.com/zhouhaoyi/ETDataset)，固定 commit 为 `1d16c8f4f943005d613b5bc962e9eeb06058cf07`，路径为 `ETT-small/ETTh1.csv`。`data/ETTh1.csv` 保留下载的全部原始字节，**没有重排、填充、归一化或截断原文件**。

- SHA256：`f18de3ad269cef59bb07b5438d79bb3042d3be49bdeecf01c1cd6d29695ee066`
- 字节数：2,589,657
- 原始行数：17,420 条观测（不含表头）
- 数值变量及顺序：`HUFL,HULL,MUFL,MULL,LUFL,LULL,OT`
- 时间戳列：`date`；频率为每小时。
- `scripts/prepare_data.py` 使用 Python 标准库校验固定 SHA256、行数、列顺序、严格一小时间隔、时间唯一性以及全部数值有限且无缺失。
- 校验结果与每个划分的真实起止时间保存在 `data/manifest.json`。

## 为什么不是对 17,420 行直接按比例划分

TFB 的 [正式论文](https://www.vldb.org/pvldb/vol17/p2363-hu.pdf) Table 5（PDF 第 6 页）明确列出 ETTh1：长度 **14,400**、7 个变量、训练/验证/测试比例 **6:2:2**。当前克隆的 TFB commit `889459188ec89c9cb3c7e5ec40f30b8c0c5c2529` 中：

1. `config/rolling_forecast_config.json` 采用 `tv_ratio=0.8`、ETTh1 的 `train_ratio_in_tv=0.75`、`stride=1`。
2. `ts_benchmark/evaluation/strategy/rolling_forecast.py` 的 `_get_split_lens` 优先使用 metadata 中的 `length`，缺省时才使用序列实际长度；先计算训练+验证占 80%，随后模型内部再分训练/验证。
3. [iTransformer 官方 ETT loader](https://github.com/thuml/iTransformer/blob/main/data_provider/data_loader.py) 的 `Dataset_ETT_hour` 明确将边界写为 `12*30*24`、`12*30*24+4*30*24`、`12*30*24+8*30*24`。

因此，按 ETT 官方代码使用原始序列的前 14,400 行，并应用 TFB 的上述比例，得到相同的经典 12/4/4 个月协议。这里的“月”是实现中的固定 **30 天**，不是自然日历月。本项目通过原始数据和上述公开证据重建协议；未下载整个 TFB 云盘预处理数据包，**未声称已将云盘包与原始 CSV 做逐字节比较**。

| 划分 | 预测目标区间（0 起始、左闭右开） | 观测数 |
|---|---|---:|
| 训练 | `[0, 8640)` | 8640 |
| 验证 | `[8640, 11520)` | 2880 |
| 测试 | `[11520, 14400)` | 2880 |
| 保留但不用于此 benchmark | `[14400, 17420)` | 3020 |

不能直接将 17,420 行按 6:2:2 划分，否则会得到 10,452/3,484/3,484，改变训练时间范围和测试目标，不能与经典 ETT / TFB 结果视为相同协议。

## 窗口、归一化与指标

- 输入长度固定为 96。给定预测起点 `t`，只读取输入 `[t-96,t)`，预测 `[t,t+H)`。
- 验证集第一次预测允许读取训练集末尾已经观测到的 96 小时；测试集第一次预测允许读取验证集末尾已经观测到的 96 小时。这是官方 ETT 滑窗协议，无需舍弃分界后的前 96 个目标。
- 测试以 1 小时步长滚动，不更新模型；后续测试窗口允许使用预测起点以前已经观测到的测试历史，但不能读取该起点以后的真实值作为输入。
- 同一预测长度下，各模型评估完全相同的预测起点、7 个目标变量和预测步；测试与验证均 `drop_last=False`。
- `StandardScaler` 仅在训练区间 `[0,8640)` 拟合每个变量的均值和总体标准差，再用于验证和测试。这与 TFB 模型基类中的训练 scaler 和 forecasting strategy 的评价 scaler 一致。
- 报告主指标为标准化尺度的 MSE/MAE；对应 TFB 的 `mse_norm`/`mae_norm`。把三个维度（窗口、预测步、7 变量）的误差按元素等权平均，不能对最后不足一批的 batch 与完整 batch 做等权平均。
- 展示曲线可还原为原始物理尺度，曲线必须标明尺度，不能将原始尺度指标与标准化尺度指标混用。

| 预测长度 H | 训练窗口数 | 验证窗口数 | 测试窗口数 |
|---:|---:|---:|---:|
| 96 | 8449 | 2785 | 2785 |
| 192 | 8353 | 2689 | 2689 |
| 336 | 8209 | 2545 | 2545 |
| 720 | 7825 | 2161 | 2161 |

训练窗口数为 `8640-96-H+1`；验证/测试窗口数为 `2880-H+1`。这些是可用窗口总数；若训练 loader 按官方设置丢弃最后不足一批的样本，应在训练配置中记录，不能将训练规则用于测试。

## 复核命令

在项目根目录运行 `python scripts/prepare_data.py`。已有文件会直接验证；缺失时下载固定 commit 的文件。需要重新下载时使用 `python scripts/prepare_data.py --force-download`。下载完成且通过校验之后才会替换本地源文件；不匹配的数据会报错并停止。
